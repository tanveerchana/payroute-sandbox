# PayRoute Sandbox design

A portfolio payment orchestration console by Tanveer Singh. Every provider, payment and settlement is simulated. No payment networks, card details or real funds. Account access uses email; payment simulation does not collect customer identity.

The implementation follows the authorized React/TypeScript/Vite frontend and Node Vercel workspace API with PostgreSQL compare-and-swap supplied by the project shared adapter. It uses a deterministic domain reducer for atomic commands. The console uses a light neutral background, white panels, slate text and blue actions. Base text is 16px, transaction rows use 14px, metadata is at least 12px, and controls have a 44px minimum touch target. Spacing follows an 8/16/24px rhythm. A left navigation exposes Overview, Transactions, Routing, Reconciliation and documentation. The main overview puts the payment simulator first and pairs it with a compact, ordered provider summary; transaction detail exposes every attempt and reason. Responsive layouts retain the primary actions on mobile.

Amounts are accepted as decimal strings and stored in integer minor units for AUD, USD, CAD and EUR. More than two decimal places are rejected. An idempotency key binds a normalized payment request; replay returns the original payment, conflicting reuse fails. Retry occurs only for simulated provider unavailability, and hard declines terminate. Provider settings affect new payments only. At 200 payments the workspace rejects new payments until an explicit reset, preserving idempotency for the workspace lifetime.

Settlement reconciliation parses a bounded CSV statement, compares every successful payment, and flags missing, duplicate, unexpected, currency and amount mismatches. A generated statement intentionally contains three exceptions for demonstration. All dashboard figures derive from workspace transactions; money totals are currency scoped. Simulated timestamps and deterministic latency are identified as such.

Alternatives considered: a local-only preview would be simpler but cannot provide shared concurrency guarantees; live provider integration would introduce real financial data and is outside the sandbox brief. The chosen hosted workspace reducer provides inspectable behavior without real funds. Persistence failure is shown prominently, with no silent local-state fallback. The access wrapper offers sign in, sign up and an explicit guest demo. Account workspaces use cookie sessions and membership roles; the browser does not store account tokens. Only demo mode creates a browser-generated 256-bit bearer workspace token. Owners manage providers, route order and reset; editors can simulate and reconcile; viewers can inspect and export. The API independently authorizes commands. Mode and workspace changes remount the application so previous workspace state is not shown during the transition.
